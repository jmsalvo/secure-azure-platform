# `v0.2` Hardened AKS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a hardened AKS cluster (`environments/dev/aks/`) with a
public-but-firewalled API server, split system/user node pools, and a
minimal proven-working sample workload — plus the module capability and
CI additions it depends on.

**Architecture:** Two repos, four sub-projects, in dependency order:
(1) `terraform-azure-modules`' `aks` module gains two additive variables
(`api_server_authorized_ip_ranges`, `user_node_pool`), released as `v0.2.0`;
(2) `secure-azure-platform`'s `bootstrap/` gains the `aks` stack's resource
group and an opt-in Defender for Containers toggle, applied by hand;
(3) `networking` gains a dedicated `aks` subnet; (4) the new `environments/dev/aks/`
stack, `tf-stack`'s new destroy mode, and `ci.yml`'s new `plan-aks`/`apply_aks`/
`destroy` jobs land together.

**Tech Stack:** Terraform >= 1.6, azurerm ~> 4.0, GitHub Actions (OIDC),
`terraform test` (`mock_provider`), Kubernetes manifests applied by hand via
`kubectl`.

**Spec:** `secure-azure-platform/docs/superpowers/specs/2026-09-12-v0.2-hardened-aks-design.md`

## Global Constraints

- Repo-wide versioning in `terraform-azure-modules` — one tag (`vX.Y.Z`) covers
  every module; this change is `v0.2.0` (additive, non-breaking). See
  `terraform-azure-modules/docs/decisions/0001-repo-wide-versioning.md`.
- `terraform-azure-modules` commits follow Conventional Commits
  (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `ci:`, `refactor:`).
- Every module behavior change needs matching `.tftest.hcl` coverage
  (`terraform -chdir=modules/aks test`, no Azure credentials needed —
  `mock_provider "azurerm"`).
- `secure-azure-platform` stacks follow the `bootstrap`-owns-RG-and-RBAC
  pattern (ADR 0002) — a stack never creates its own resource group or role
  assignments.
- **Ask before merging any PR, and before any action that triggers a live
  `terraform apply`** (merging to `main` auto-triggers `apply_*` CI jobs for
  any changed stack — there is no required-reviewers gate). `bootstrap/` is
  the one exception that's never CI-applied — it's run by hand by the user,
  who holds subscription-Owner credentials Claude does not have.
- The user runs all `az`/`gh` CLI commands themselves in their own PowerShell
  window and pastes output back; Claude creates branches/commits/PRs and
  Bash-based `gh` calls directly.

```hcl
variable "user_node_pool" {
  description = <<-EOT
    Optional second (user) node pool, for application workloads separate from
    the system pool:
      - name             pool name (default "user")
      - vm_size          VM SKU (default "Standard_D2s_v5")
      - node_count       node count, or initial count when autoscaling (default 2)
      - min_count / max_count  set both to enable the cluster autoscaler
      - os_disk_size_gb  OS disk size in GB (default 64)
    Null (the default) creates no second pool — every node runs in
    default_node_pool, matching v0.1.0 behaviour.
  EOT

  type = object({
    name            = optional(string, "user")
    vm_size         = optional(string, "Standard_D2s_v5")
    node_count      = optional(number, 2)
    min_count       = optional(number)
    max_count       = optional(number)
    os_disk_size_gb = optional(number, 64)
  })
  default = null

  validation {
    condition     = var.user_node_pool == null || var.user_node_pool.node_count >= 1
    error_message = "user_node_pool.node_count must be at least 1."
  }

  validation {
    condition     = var.user_node_pool == null || (var.user_node_pool.min_count == null) == (var.user_node_pool.max_count == null)
    error_message = "set both user_node_pool.min_count and user_node_pool.max_count to enable autoscaling, or neither."
  }

  validation {
    condition = (
      var.user_node_pool == null || var.user_node_pool.min_count == null || var.user_node_pool.max_count == null
      ? true
      : var.user_node_pool.min_count >= 1 && var.user_node_pool.max_count >= var.user_node_pool.min_count
    )
    error_message = "when autoscaling, user_node_pool.min_count must be >= 1 and no greater than max_count."
  }
}
```

demonstrates pod-to-pod isolation, not operator access.

- [ ] **Step 2: Add the `destroy` job**

Append at the end of the `jobs:` block:

```yaml
  destroy:
    if: github.event_name == 'workflow_dispatch'
    runs-on: ubuntu-latest
    environment: dev-apply
    # Same concurrency group as this stack's apply job — a destroy can never
    # run alongside an apply of the same stack.
    concurrency:
      group: apply-${{ github.event.inputs.stack }}
      cancel-in-progress: false
    permissions:
      contents: read
      id-token: write
    env:
      ARM_CLIENT_ID: ${{ vars.ARM_CLIENT_ID_APPLY }}
      ARM_TENANT_ID: ${{ vars.ARM_TENANT_ID }}
      ARM_SUBSCRIPTION_ID: ${{ vars.ARM_SUBSCRIPTION_ID }}
      ARM_USE_OIDC: "true"
    steps:
      - name: verify confirmation matches the selected stack
        shell: bash
        run: |
          set -euo pipefail
          if [ "${{ github.event.inputs.confirm }}" != "${{ github.event.inputs.stack }}" ]; then
            echo "::error::confirm ('${{ github.event.inputs.confirm }}') must exactly match stack ('${{ github.event.inputs.stack }}') — aborting before touching Terraform."
            exit 1
          fi
      - uses: actions/checkout@v4
      - uses: ./.github/actions/tf-stack
        with:
          stack: ${{ github.event.inputs.stack }}
          mode: destroy
          terraform-version: ${{ env.TERRAFORM_VERSION }}
          needs-tfstate-storage-account: ${{ (github.event.inputs.stack == 'key-vault' || github.event.inputs.stack == 'aks') && 'true' || 'false' }}
```

Note the operational rule from the design spec's "On-demand destroy"
section (documented, not enforced in code): destroying `aks` — the top of
the dependency chain — is always safe. Destroying `networking`,
`observability`, or `key-vault` while `aks` (or anything else) still depends
on it is the dangerous direction; only do that after confirming nothing
above it still exists.
